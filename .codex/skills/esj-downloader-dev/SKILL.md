# ESJ Project Workflow

This single file supplies the project workflow, ownership, verification selection, and release gates. Inspect relevant source/configuration/tests for implementation details; no other project skill or skill reference is required. Source paths below are relative to the repository root; UI metadata is relative to this skill folder.

## Establish the task and source

Inspect the request, current branch/commit, `git status --short`, scoped diff, `package.json`, and nearby source/tests. When latest source is requested, fetch the relevant remote and compare exact commits before assessing the skill or code. Preserve local changes before an authorized fast-forward; inspect divergence before choosing integration. Use the lockfile and CI runtime configuration; install missing/outdated dependencies with `npm ci`.

| Request                   | Work and completion                                                                                                                                                                                                                                                        |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Investigation or review   | Trace affected behavior and existing evidence. Report actionable findings with locations, triggers, and impact; distinguish static findings from reproduction. Run checks within the requested validation scope.                                                           |
| Feature, fix, or refactor | Make a focused change. Reproduce the relevant boundary, reuse existing evidence, and add automation only for a concrete uncovered data, asynchronous, protocol, or resource boundary that synthetic inputs reliably reproduce. Verify ordinary page defects on real pages. |
| Documentation or skill    | Check the described behavior and affected text. User-visible changes require checking both READMEs; wording-only README/release-note edits use text and formatting checks. For skills, apply the single-file self-check below.                                             |
| Release work              | Apply the release steps for assessment, authorized publication, or verification of an existing release. An evidence-backed blocker verdict completes an assessment.                                                                                                        |

State compatibility, migration, or explicit invalidation before changing cache/schema, persisted selection, configuration, cancellation semantics, or other major behavior. Ask for product decisions that remain unsettled after inspecting the request and evidence.

Commit, push, version changes, tag creation/push, GitHub Releases, and committing `dist/` are distinct authorization scopes; continue operations already authorized. Builds may regenerate ignored `dist/`. Preserve unrelated edits and stage explicit authorized paths. Commit/PR titles follow `type: subject` without scope.

New contribution branches start from the latest `dev`; continue an existing branch/checkout when the request specifies it. Target contribution PRs at `dev`, and synchronize stable hotfixes back to `dev` after merging into `main`. Discuss larger behavior/cache-format changes in an Issue before implementation, using existing approved discussion where available. Keep Issue/PR creation and posting within the user's authorized scope; describe the problem, change, validation, and unverified range in the PR.

## Preserve affected contracts

- **Preparation:** detail uses the current document; forum fetches detail text with a deadline covering body reading. Show cancellable preparation before directory/cache readiness; offer the previous export. Preparation acquires neither book lock nor cache writer. Closing aborts requests and excludes late directory/cache/error results from the task and later windows.
- **Selection and directory:** `ChapterSelection` uses immutable, unique, sorted, nonempty absolute indexes and `all | selected`. Arbitrary sparse selections and ranges share one plan; only selecting the entire source directory becomes full-book mode. Tasks and the passive static directory copy share exact indexes and complete chapter text; mapping failure falls back to a task list. Preserve search, selections, and inputs across view/language updates.
- **Cache:** full/selected tasks share a book lock and absolute-index v3 cache. Preview is read-only and avoids chapter/Blob loading. Claim atomically rechecks compatibility and invalidation consent; release the lock before re-confirmation and retain selection, directory, and custom filename. Full success clears the book cache; partial success seals writes and calls `finishForTask()` to close the writer while retaining accumulated chapters. Define legacy migration/invalid-cache recovery and prevent stale writes from resurrecting cleared data.
- **Summaries and counts:** `normalizeChapterSelectionSummary` reads legacy and v2 multi-range summaries. Invalid summaries retain their containing historical record and are classified as selected. Display/diagnostics may shorten interval detail; snapshots/history keep the full selection. `readyChapterCount` concerns selected chapter records, `bookChapterCount` whole-book inventory, and `persistedCount` confirmed writes.
- **Cancellation and ownership:** ordinary cancellation aborts network/waits, then uses an independent signal and bounded cache flush; it may upgrade to discard while saving. Only the owning writer clears the book cache. Every exit, including initialization or cleanup failure, stops heartbeat and releases the lock. Chapters/cancellation/lock belong to a task; page state holds handles, summaries, and the latest export. Gate stale callbacks by `taskId`; legacy sync events require read-only ownership checks. Failure/cancellation preserves the previous export.
- **Exports:** recover/repair/assemble against the fixed selected plan; unselected chapters never create missing-chapter decisions or placeholders. Explicitly accepted placeholders exist only in the export snapshot. Book HTML and current-page HTML retain distinct layouts/resource ordering; images resolve against the initiating page URL. Normalize/validate fonts before export; mapped fonts disable TXT. Book/selected tasks support TXT/HTML/EPUB; current-page export supports TXT/HTML, uses native site unlock, takes no book lock, and does not publish a book result.
- **Original results and resources:** custom filenames belong to the captured result and leave book metadata, cache identity, history, and diagnostic attribution intact. Trim names, remove an existing supported extension, replace forbidden filename characters, fall back to the book title when blank, and append the chosen format. Retained exports record their original task identity; missing source identity must not attribute to a newer task. EPUB reuse respects generation settings and invalidation generation; late output cannot restore an invalidated Blob. Closing the format view leaves generation running; old generation cannot change a new task's title. Book object URLs revoke after 60 seconds with detached history; single URLs revoke immediately after triggering/removal with awaited history. In the single-page workflow, preserve the actual download-trigger marker through subsequent cleanup/history failures.
- **Settings and protected decisions:** capture image settings before cache preview, concurrency at task assembly, and EPUB settings when generating the original result. Preserve image/cache compatibility. Password, font, and missing-chapter decisions serialize within a task. Site authorization returns structured results; rejection is retriable and never becomes an ordinary failure or cached chapter. Skipped chapters remain eligible for later retry; skip-all affects the current round, and explicit missing-chapter retry starts a new round. Remembered passwords stay in task memory and clear on rejection/finalization.
- **Diagnostics and locale:** neutral diagnostic rules/redaction/budgets belong to the manager, task/environment/page-close wiring to runtime, JSON to diagnostic export, storage failures to storage isolation, and presentation/log text to UI. Preserve original task identity, terminal dominance, listener cleanup, GM-failure isolation, and batched restoration/log budgets. Pure locale/catalog logic stays independent of storage/DOM; UI composes stored preference → site hint → browser fallback at call time and owns refresh/subscriptions. Keep novel data, metadata, URLs, and ESJZone `status === 206` protocol text intact; manually localize `zh-TW` using Taiwanese terms.
- **Shared evidence:** use minimal synthetic fixtures. Credentials, full response bodies, novel bodies/HTML, binary/encoded image/font payloads, raw IndexedDB records, and uncleaned stacks stay out of commits and shared logs/diagnostics. Review diagnostic JSON for publicly shareable titles, URLs, and chapter details. Keep run-specific evidence in the task/PR; repository guides contain reusable rules, not acceptance logs or pending statuses.

## Select verification

Reuse one main automated proof per input/action/result. Add a case only for a reliably reproducible uncovered business boundary. Ordinary buttons, labels, injection, language refresh, dragging, scrolling, and layout use real ESJZone pages with a browser/userscript manager; fixing a page defect alone does not require a synthetic regression test.

| Changed behavior                                                                                                          | Checks                                                                                                                                   |
| ------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| Ordinary page/UI behavior                                                                                                 | `npm run build` and affected real-page checks; reuse existing automation only for changed data/asynchronous boundaries                   |
| Selection, parsing, images, fonts, or export data/resources                                                               | Focused existing tests, then `npm run check`; inspect relevant actual HTML/EPUB files/readers                                            |
| Protocol, authorization, pending decisions, or request isolation                                                          | Relevant protocol/cancellation contracts, `npm run check`, real permission/password checks; stress when lifecycle/queue changes          |
| Cache, migration, history isolation, ownership, cross-page state, scheduling, byte budgets, backpressure, or cancellation | Affected download/cache contracts, `npm run check`, `npm run test:stress`                                                                |
| Diagnostics, GM failures, task attribution, page close, or log budgets                                                    | Relevant manager/runtime/recovery contracts, `npm run build`; stress for changed lifecycle; relevant real JSON download/copy checks      |
| Broad change, test cleanup, or preparation for commit/PR                                                                  | `npm run build`; run remaining stress tests when cache/lifecycle tests or their stress coverage change                                   |
| Release candidate                                                                                                         | `npm run build` and `npm run test:stress`, plus relevant native acceptance gates                                                         |
| Documentation/skill only                                                                                                  | Check text, explicit Prettier for changed files, paths/metadata and `git diff --check`; apply submission checks when preparing commit/PR |

Start with a focused command such as `npm run test -- tests/download/download-selection.test.ts`. `npm run build` runs typecheck, ordinary tests, ESLint, formatting, and Rollup; it does not run stress. CI has a separate stress job, and the release workflow runs stress before publication. `build:fast` is typecheck plus Rollup for local iteration. Recheck definitions after command/workflow changes. Reuse evidence only while source/dependencies/configuration remain relevantly unchanged; rerun affected checks after edits/failures.

Retain affected main fault-injection evidence for storage unavailability/quota, transaction abort, failed read/write/migration, and lost lock/writer. Classification tests alone do not prove retry, propagation, preserved data, or finalization. Select existing lifecycle cases rather than duplicating the full matrix for each entry. Protect preparation cancellation, atomic preview/claim, arbitrary selections/summary compatibility, late callbacks, retained exports/inputs, and resource limits when affected.

Use `tests/support/` fixtures/fakes/mocks, `createDeferred()` for ordering, and `useFakeClock()` for deadlines/backoff/heartbeats. Pure tests use Node; jsdom is for DOM-dependent data/asynchronous boundaries and output structure. Close the channels/databases actually created and consume/clear timers. Automated tests must not access live ESJZone, real network, or production IndexedDB. A fake repository does not prove an IndexedDB transaction; registered-resource cleanup does not prove every production resource is leak-free.

Assert independent business outcomes, codes/parameters, retained inputs, resource references, and cleanup. Avoid UI snapshots, CSS/layout constants, copied interface prose, formatter/`t()`-derived expected values, fixture self-tests, and forwarding/call-count tests without a business contract. Catalog automation checks keys/interpolation; humans review Taiwanese terminology. Retain representative stress for read-only large previews, Blob byte budgets, selective invalid-cache repair, sparse/late-range isolation, and slow-write backpressure. Large loops alone do not measure browser time/memory limits.

For relevant native checks, record source SHA, browser/manager versions, entry, scenario, formats, and result: detail/forum/single injection; slow/late preparation and cancel; empty/all/sparse selection, original directory/search/mobile controls, retained filename; native unlock/password/font/missing-chapter actions; normal stop/clear/upgrade/cross-page conflict; actual file trigger, resources and reader display; open-view locale/input refresh, settings, history/cache/diagnostics. Chrome + Tampermonkey is the active release combination. Record only validated combinations; synthetic fixtures do not establish native acceptance. Mark unavailable checks unverified in the task/PR.

## Release phases

For assessment use steps 1–4; for authorized publication apply 1–5; for an existing published release use 6 and relevant candidate/policy evidence from 1–2.

1. **Candidate:** inspect current branch/commit, clean candidate state, package/lockfile version, diff, tags, synchronized remote branch, and relevant Issues/PRs. Report unavailable remote evidence as unverified. A future tag need not exist during assessment.
2. **Policy/provenance:** inspect `.github/workflows/release.yml`, `script-meta.js`, and `rollup.config.js`. Tag is exactly `v<package.json version>`; supported alpha/beta/rc commits belong to `dev` and stable `x.y.z` to `main`. Build `dist/esj-novel-downloader.user.js` from the exact candidate and verify header/version. Old artifacts/tags alone do not establish provenance.
3. **Evidence:** require `npm run build` and `npm run test:stress`, affected README parity and relevant guide/command consistency. Add applicable migration/fault recovery, selection/cache/history isolation, cancellation, export/font/image/EPUB reuse, locale, and real-page/reader checks.
4. **Verdict:** table gate, evidence/command, result, unresolved risk. Ready requires passing evidence for every applicable gate, including manual/migration checks; otherwise identify blockers and required action. State accepted nonblocking limitations. Assessment completion does not imply blocker implementation or publication authorization.
5. **Authorized publication:** carry out approved operations only. Pushing `v*` triggers building and GitHub Release/asset creation; account for that effect before pushing. Inspect existing runs/releases before retrying. Preserve candidate/tag/source relationships and workflow-built assets.
6. **Published verification:** inspect actual tag SHA/ancestry, workflow result, prerelease flag and uploaded `esj-novel-downloader.user.js` header/version against the candidate. Record installation/upgrade and affected browser flows; keep unverified checks pending in the report.
